## Part A — the two hash systems

They are independent. Neither calls the other, and they disagree about which hierarchy is authoritative.

| | `canonical_program_hash` (v1) | `compute_merkle_hashes` |
|---|---|---|
| Location | `ir/canonical_hash.rs` | `ir/hash_pass.rs` |
| Public API | **yes** (`pub fn`) | **yes** (`pub fn`) |
| Production caller | `module_store.rs:263` → `CompiledProgram.canon_hash` | `module_store.rs:255` → `Ir.decl_hash` |
| Persisted | yes, in `CompiledProgram` | yes, `decl_hash` is a serde field of `Ir` |
| Survives serialization | recomputed from `Ir`+`Index` | **stored**, so a stale table can be deserialized |
| Versioned | **yes** — `CanonHashCfg { schema_version, algo_version, flags }`, domain-separated headers | **no version, no domain separation** |
| Hierarchy source | **`Index` path prefixes** | **intrusive `decl_children`** |
| Dense-ID dependent | no (proved, M0.5 C5) | **yes** — see the ordering defect below |
| Complexity | O(n·depth) path work + O(n log n) sorts | O(n + refs) |
| Incremental | no | no (single backward pass) |
| History-independent | **yes** (proved, M0.5 C1/C5/C6/C10) | not established |

### A defect in `compute_merkle_hashes`, found by the coverage matrix

`incidence.target` **does not change the merkle hash** (§B). The cause is an ordering assumption:

```rust
for i in (0..num_decls).rev() { …            // children assumed to have HIGHER ids
    if let Some(h) = ir.decl_hash[child] { hasher.update(&h.0); }   // silently skipped if absent
```

The pass runs one backward sweep, assuming every child and every reference target has a **higher** `DeclId` than the declaration referring to it. When that does not hold, the missing hash contributes **nothing at all** — not a marker, not a zero — so a declaration with an unresolved reference hashes identically to one with no reference. Arc declarations are appended after the nodes they target, so on realistic input the targets are *always* unresolved and `incidence.target` is invisible.

This is **not** repaired here: `hash_pass.rs` is outside the authorised edit surface for this phase, and repairing it would change stored `decl_hash` values. Recorded as a defect with a characterisation test.

## Part C — the v1 contract

### C.1 What v1 covers

Declaration **kind**; declaration **path** (as name); **skeleton shape** via a Prüfer encoding of the path-derived forest; **ordered incidence topology** — owning edge path, arc index, reference slot, sign, target path.

### C.2 What v1 does not cover

**Annotations** (tags and values), **incidence weights**, **incidence annotations**, **`bases`**, `Ir.meta`, and the **intrusive hierarchy**. Values of every kind are absent, so no `ValueR` distinction — including `+0.0` vs `-0.0`, `±Inf` and NaN payloads — reaches v1 at all.

### C.4 Consequence — stated explicitly

> **v1 does not cover the full semantic state.** It is **V1-STRUCTURAL-ONLY** and **must not be used as the sole full-state convergence identity.** Two programs differing only in weights, annotations or inheritance produce the same v1 digest.
>
> v1 is **not changed** under `algo_version = 1`. Documentation is corrected additively; the algorithm is frozen. Completing semantic coverage is the job of `semantic_snapshot_hash` v2 (§G).

This also bears on **M2e**: the U2 authority flip changes the hash's hierarchy source from paths to links. §F shows the two agree on all 96 fixtures today, so the flip would not move any current digest — but it is still a v1-output change in principle and therefore requires an `algo_version` decision, not a silent switch.

## Part D — numeric determinism: **NUMERIC-SAFE**

### Audit

Exactly **two** `partial_cmp` occurrences exist in `hymeko_core/src` and `hymeko_hnn/src`:

| Site | Classification |
|---|---|
| `common/ids_impl.rs:33` — `PartialOrd for Id<T>` | **non-floating wrapper delegating to total `Ord`** (integer) |
| `canonical_hash.rs` — `PartialOrd for Leaf` | **non-floating**, delegates to `Ord` on `[u8;32]` and `u64` |

**Neither is NaN-reachable. There is no float `partial_cmp` anywhere in an identity path.** Every sort in the hash paths is `sort_by_key` over integers or `sort()` over `[u8;32]` — total orders by construction. `total_cmp` appears nowhere, and is needed nowhere *today* because no float ordering exists in these paths. No mechanical replacement was performed, per the brief.

### Measured behaviour

`ValueR::Num` is hashed via `to_le_bytes()`, so it is bit-preserving. Measured against the merkle hash:

| Case | Distinguished? |
|---|---|
| `+0.0` vs `-0.0` | ✅ |
| `+Inf` vs `-Inf` | ✅ |
| two distinct NaN payloads | ✅ |
| list order `[1,2]` vs `[2,1]` | ✅ |

All satisfy **U4**. Repeated-run determinism verified over 8 iterations for both hashes.

**The boundary, stated:** NUMERIC-SAFE holds *because* no float ordering exists yet. v2 introduces canonical ordering over values (§G), and that is precisely where `total_cmp` becomes mandatory. The audit's conclusion is "safe now, and here is the exact place it would stop being safe" — not "safe forever".

## Part E — iterative traversal: **ITERATIVE-PASS**

`compute_subtree_hashes_with_kinds` previously contained an inner `fn rec(...)` descending one stack frame per hierarchy level. It is now an explicit post-order fold over a `Vec<Frame>` with `Enter`/`Exit` frames.

**Preserved exactly:** child hashes are collected in `children` order then sorted lexicographically (so traversal order cannot influence output); the per-node domain and header are unchanged; nodes unreachable from `roots` still fold to `HashId([0;32])`.

**Added:** checked indices throughout, and an `on_stack` guard so a malformed `children` containing a cycle terminates deterministically instead of looping. Cycles are unreachable by construction — `children` derives from strictly shortening path prefixes — so this is defence, not a live path. No `unsafe`, no dynamic dispatch.

**Memory delta:** one `Vec<bool>` of length *n* (~1 byte/declaration, ~3% of the existing `memo` table) plus an O(depth) heap stack replacing O(depth) call stack.

### Equivalence evidence

| Evidence | Result |
|---|---|
| 5 frozen known-answer vectors | **identical** |
| 96-fixture corpus digest | **identical** (`525fa75c…`) |
| M0.5 invariance suite (14 tests) | **all pass** |
| Depth 1 000 / 10 000 | **pass** (previously aborted at 458) |
| Depth 16 384 | **pass** — no stack ceiling within the probed range |

### The new limit is memory, not depth

Depth 100 000 fails, but **not** in the traversal. A chain of depth *d* stores Σ(1..d) `SymId`s across its path keys — O(d²). At d = 100 000 the probe reached a **46 GB working set** before I stopped it.

**This exceeded the 16 GB cap in `CLAUDE.md` §4.** It was a diagnostic probe, not a queued run, and I stopped it on observation — but it is a budget breach and is reported as one, not omitted. The M0.5 boundary test has been capped at 16 384 so the suite can never climb into that region again.

The finding itself matters: **path-based hierarchy identity is quadratic in depth.** That is an independent argument for U2 — parent links are O(1) per declaration; paths are O(depth).

## Part F — coherence: **COHERENT**

New: `hymeko_core/src/ir/coherence.rs`, additive and read-only.

Validates: indexed ids in range; live declarations present in the index (nodes and edges — anonymous arcs are explicitly exempt); path-prefix parent equals `DeclNode.parent`; sibling chains finite, terminating at `last_child`; child back-links; parent acyclicity; `kind` agreeing with `decl_to_*`; no declaration in two record tables; record back-pointers; parallel-array lengths.

Findings are **structured** (ids and counts only — never caller-supplied strings, so a hostile `Ir` cannot make the report echo a payload), **bounded** by `max_findings`, **deterministically ordered** (the index is sorted before use, so `HashMap` iteration order cannot reorder the report), and report `total` plus `truncated` so more than the first divergence is visible.

### Corpus result

```
lowered=96  clean=96  diverged=0
```

**Current lowering is fully coherent.** Every corruption test is caught: parent mismatch, parent cycle, sibling cycle, child back-link, `decl_to_*` mismatch, record back-link, index-path disagreement, array-length mismatch, plus bounded-and-deterministic reporting.

**This corrected a prediction of mine.** The M0.5 migration document said of M2e step 1: *"Expect some: nothing has ever enforced agreement, so nothing guarantees it."* That was wrong. Nothing enforces agreement, and agreement nonetheless holds across the whole corpus — an unenforced invariant that happens to be maintained. The reasoning error was treating "not enforced" as evidence of "violated"; it is only evidence of "unprotected". The invariant is now protected by a validator and a corpus test.

## Part G — `semantic_snapshot_hash` v2 (specification only)

### G.1 Three distinct identities

| Name | Cost | History | Purpose |
|---|---|---|---|
| `commit_chain_digest` | **O(delta)** | sensitive | every commit, incl. the 100 Hz path; replay and conflict detection |
| `semantic_snapshot_hash` | O(graph), incrementally maintainable | **independent** | checkpoint, audit, cross-replica convergence |
| `presentation_digest` | O(layout) | independent | optional editor layout; **never** part of semantic identity |

### G.2 Requirements

History-independent; independent of dense and generational IDs; **complete over every semantic field** (closing the §B gaps: annotations, values, weights, bases, incidence annotations); deterministic for **all** IEEE bit patterns; explicit about ordering (U1: arc and slot order preserved) and multiplicity (U3: duplicates distinct); built on the **canonical hierarchy** (U2) rather than the derived index; `algo_version`-tagged; compatible with incremental maintenance.

### G.3 Encoding rules

- **Domain separation:** every stage gets a distinct 8-byte domain, as v1 already does (`SKELETON`, `INCIDENC`, `PROGRAM\0`). v2 adds `ANNOTATE`, `WEIGHTS\0`, `BASES\0\0\0`, `VALUE\0\0\0`.
- **Field tags:** every field contributes a 1-byte tag before its payload, so no two field layouts can alias.
- **Length framing:** every variable-length item is preceded by its `u64` length. `hash_pass` already does this for tag strings; v2 makes it universal.
- **Canonical numeric encoding:** `f64` as **`to_bits().to_le_bytes()`**, never a formatted or normalised value — this is what keeps `-0.0` distinct from `+0.0` and preserves NaN payloads (U4). Ordering, where needed, by **`total_cmp`**.

### G.4 Incrementality — the honest part

**A Merkle fold alone does not make v2 incremental.** M0.5 measured v1 at 10.74 ms / 15 000 declarations, and M0.6 confirms the cost is not in the subtree fold — making that fold iterative moved the total by ~4%. The expensive work is four **whole-graph** stages:

| Stage | Today | What incrementality requires |
|---|---|---|
| Path reconstruction | O(n·depth), rebuilt per hash — and O(d²) in memory for deep chains (§E) | **Eliminated** by U2: read `parent` links, do not rebuild paths |
| Skeleton construction | full forest rebuild | dirty-subtree marking; rebuild only changed regions |
| Prüfer encoding | whole-tree, leaf-by-leaf with a global heap | **The hard one** — inherently global; needs replacing, not patching |
| Incidence sorting | full sort of all incidences | an incrementally maintained ordered index |

### G.5 Options compared

| # | Option | Verdict |
|---|---|---|
| 1 | Incrementally maintained ordered authenticated indexes | Correct long-term, highest complexity; needs an authenticated ordered structure the repo does not have |
| 2 | **Per-entity stable semantic digests + order-independent keyed aggregation** | **Recommended first stage.** Each declaration/incidence gets a digest from its own fields plus its children's digests; aggregation is keyed and order-independent, so a change touches O(changed × depth) — and depth is 5 (M0.5). Drops the Prüfer stage entirely, which is what makes it incremental. |
| 3 | Periodic full canonical checkpoint + commit-chain hot path | **Already decided (U6)** — the interim answer. v2 need not be incremental on day one. |
| 4 | Hybrid dirty-subtree / index updates | The convergence point of 1 and 2; adopt once 2 is measured |

**Staged recommendation with falsification gates:**

| Stage | Gate that would falsify it |
|---|---|
| V2-a: define encoding, implement full computation | field-coverage matrix shows any semantic field still missed |
| V2-b: per-entity digests + keyed aggregation | full and incremental computations disagree on any graph |
| V2-c: incremental maintenance | update cost is not O(changed × depth) at 10⁵ declarations, or exceeds 10 ms at the 100 Hz budget |
| V2-d: retire the periodic checkpoint | only after V2-c meets its gate under sustained load |

The falsifier for the recommendation as a whole: **if order-independent keyed aggregation cannot express U1's ordered slots**, option 2 fails and option 1 becomes necessary. Ordering must be encoded *inside* each incidence's digest (slot index as a tagged field), not in the aggregation order.
