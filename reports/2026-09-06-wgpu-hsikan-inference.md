Date: 2026-09-06

## Outcome

The existing `hymeko_wgpu` operation framework now owns a fused, inference-only
signed-HSiKAN dispatch. It consumes GPU-resident node features, signed incidence,
Catmull--Rom control points derived by the existing host spline owner, gate
parameters, and a caller-owned output tensor. It does not introduce an IR,
topology owner, trainer, optimizer, or CUDA implementation.

The mathematical semantics remain owned by Nagare's closed-form HSiKAN path.
This boundary adds the WGPU execution mechanism needed by the canonical
`Ir -> ExecutionPlan` consumer.

## Changed ownership

- `operations::hsikan`: validated builder and repeatedly encodable prepared
  dispatch, integrated into the existing `OperationFactory` and `PipelineCache`.
- `shaders/hsikan.wgsl`: gather, output-major highway gate, signed branch mean
  with the empty-branch denominator clamped to one, and outer spline sum.
- `ResourceFactory`: typed `u32` and `i32` uploads beside the existing `f32`
  upload; the allocation implementation is shared privately.
- `KernelId::Hsikan` / `LayoutId::Hsikan`: one pipeline identity and a fixed
  eight-storage-buffer plus one-uniform binding contract.

The public-symbol inventory was regenerated by the canonical
`contract-symbols` owner.

## Discriminating evidence

`hymeko_wgpu/tests/hsikan.rs` executes the shader on:

`NVIDIA GeForce RTX 3070 Laptop GPU [Vulkan] DiscreteGpu (driver NVIDIA 595.84)`

The fixture contains positive and negative incidence and an empty negative
branch. Every finite output satisfies the predeclared bound

`abs(gpu-cpu) <= 5e-5 + 2e-4 * abs(cpu)`.

The second test proves that typed upload length and output shape violations are
rejected before dispatch. The full canonical signed-HSiKAN comparison remains
the downstream Nagare Slice-2 gate; this boundary makes no end-to-end or
performance claim.

## Explicit limits

- This is inference only; no backward or training path is claimed.
- Vertex-index range and canonical provenance are the responsibility of the
  Nagare plan compiler, which derives private incidence arrays from canonical
  `hymeko_core::Ir`. This low-level operation accepts already uploaded buffers.
- No CUDA owner exists and no CUDA implementation is justified by this work.
- No speedup or memory ratio is reported. Those require the canonical Nagare
  execution path, warm-up, repeated measurements, and raw records.
