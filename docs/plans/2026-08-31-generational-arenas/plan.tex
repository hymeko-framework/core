\section*{Scope}
Core-only (\texttt{hymeko/core}, base \texttt{67771c9}, branch
\texttt{feat/core-generational-arenas}). Generational IDs for the four canonical
entity domains only: \texttt{DeclId}, \texttt{NodeId}, \texttt{EdgeId},
\texttt{HyperArcId}. Explicitly excluded: \texttt{SymId}, interner indexes,
dense node/edge indexes, CSR row/column, shader buffer indexes. No Nagare, graph,
tensor, or WGPU change. See \texttt{id-domain-inventory.md}.

\section*{Target invariants (Part 1.2)}
\texttt{Id}=8\,B; \texttt{Option<Id>}=8\,B (niche); deletion does not renumber;
freed slot reusable; old id stale after reuse; stale detected in $O(1)$;
cross-domain still a compile error; explicit \texttt{u64} FFI form; no
\texttt{unsafe}; no unchecked narrowing; generation wrap retires the slot (never
revives a stale id); canonical hash / semantics independent of slot and
generation; the compact declaration dispatch stays 8\,B/decl (generation is
\emph{not} copied into the dispatch slot).

\section*{Representation prototypes (Part 1.3 --- measured, isolated)}
\texttt{proto\_arena.rs} at $N=10^5,10^6$, median-of-9, vs BASE (today's dense
\texttt{Vec<Rec>}, plain-index, no generation):
\begin{longtable}{lrrr}\toprule
rep & append build & random valid lookup & iteration \\\midrule
A tombstone \texttt{Slot\{gen,Option<Rec>\}} & $+37$--$47\%$ & $+72$--$122\%$ & $+63$--$75\%$ \\
B SoA \texttt{gens}+\texttt{vals} (parity) & $-7$--$-17\%$ & $\mathbf{+56}$--$\mathbf{59\%}$ & $+30$--$55\%$ \\
B$'$ interleaved \texttt{\{gen,Rec\}} & $+25\%$ & $+66$--$99\%$ & $+58$--$65\%$ \\
C dense + slot indirection & $+2$--$30\%$ & $+147$--$150\%$ & $-4$--$-8\%$ \\\bottomrule
\end{longtable}
The \textbf{valid-lookup gate is $\leq 3\%$}; the best representation (B) is
$+56\%$ --- $18\times$ over budget. Mechanistic cause: today's lookup is a single
bounds-checked load into a dense \texttt{Vec}; any generation check adds a second
array miss (B/C) or a fatter slot (A/B$'$, $+25$--$50\%$ bytes/entity). There is
no way to add a per-lookup generation check to a single-load dense lookup within
$3\%$.

\section*{Wire form (Part 1.4 --- designed and validated, \texttt{wire\_form.rs})}
8-byte \texttt{NonZeroU64}: \texttt{[63:56]} version (0), \texttt{[55:32]}
generation (24\,b; 1..=0xFFFFFE live, 0 reserved, 0xFFFFFF retired),
\texttt{[31:0]} slot (32\,b). \texttt{generation}$\geq 1 \Rightarrow$ value
$>0 \Rightarrow$ \texttt{Option} niche is 0. Known-answer + rejection + legacy
vectors all validated (frozen in \texttt{tests/basic/gen\_arena\_contracts.rs}).
Legacy bare-index $\to$ genesis handle (generation 1). Future version / gen-0 /
overflow $\to$ typed rejection, no silent reinterpretation.

\section*{Decision (Part 1.5)}
\textbf{HARD STOP on production migration.} No representation meets the
$\leq 3\%$ valid-lookup gate. Per Part 1.5 the prototype, benchmark, and this
decision are pushed; production migration is \emph{not} forced. Deeper finding:
the gate compares against an append-only \texttt{Vec}; generational arenas add
deletion-safety, and the current IR never deletes --- the two are structurally
incompatible. Generational arenas become justified only when a deletion-capable
mutable IR is a real requirement, at which point the correct baseline is a
deletion-capable structure (which already pays tombstone/compaction cost), not
the append-only \texttt{Vec}.
